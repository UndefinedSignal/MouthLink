# MouthLink — обучение

Каркас обучения модели рта. Модель принимает кадр рта (оттенки серого) и выдаёт
вектор блендшейпов в [0,1]. Два режима из плана:

1. **Дистилляция стока** — учим сеть повторять стоковый выход PICO на парах
   (кадр, стоковые блендшейпы), спаренных по времени.
2. **Персональная калибровка** — короткие сессии с подсказками выражений. Правят
   формы, где сток врёт, и добавляют каналы, которых у стока нет. Поддержан
   **частичный лейбл**: неизвестные каналы помечаются NaN и в лосс не входят.

Методика учитывает уроки трекинга языка Rulez777/PicoET-Enhance (см. проектную
заметку): главный враг — разная посадка шлема, поэтому оценка только по целым
сессиям, сильные аугментации и предобученный бэкбон.

## Формат датасета

Папка с файлами:

| Файл | Содержимое |
|------|------------|
| `frames.npy` | uint8 `[N, H, W]`, кадры в оттенках серого |
| `labels.npy` | float32 `[N, K]`, значения в [0,1]; `NaN` = канал неизвестен |
| `groups.npy` | `[N]`, id сессии (запись/надевание шлема) для каждого кадра — **важно** |
| `meta.json` | `{"height", "width", "channels": [...], "flip": {...}}` |

`flip` описывает, как меняются метки при отражении кадра по горизонтали:
```json
"flip": {"swap": [["TongueLeft", "TongueRight"], ["CheekPuffLeft", "CheekPuffRight"]],
         "mirror": ["shiftX"]}
```
`swap` — пары левых/правых каналов, `mirror` — позиционные каналы, у которых
значение переворачивается (v → 1−v). Без `flip` отражение в аугментациях отключено —
это безопасное поведение по умолчанию: отражение с неправильными метками учит
модель путать лево и право.

Без `groups.npy` весь датасет считается одной сессией (с предупреждением).

## Реальные данные: дистилляция стока

1. Шлем с модулем ml3+, запись приёмником (сток просится по умолчанию):
   `dotnet run --project MouthLink.Receiver -- --host <IP> --fps 0 --record d:\mouthrecon\s03.mlrec`
   → рядом появится `s03.stock.csv`.
2. Спаривание в датасет (по точному равенству меток):
   `python tools/mlrec_pair.py data/real1 d:\mouthrecon\s03.mlrec d:\mouthrecon\s04.mlrec --crop x,y,w,h --size 128 --every 2`
   Метки по умолчанию `instant` (стоковая постобработка без сглаживания), каналы — 33
   стоковых слота рта. Каждый файл — отдельная сессия (`groups.npy`), поэтому снимай
   шлем между записями: разные посадки и есть то, на чём проверяется модель.
3. `python train.py --data data/real1 --out runs/real1 --arch mnv3 --pretrained --cv`

`--flip` в `mlrec_pair.py` включай, только если камера рта стоит по центру лица.

## Направление языка (TongueLeft/Right/Up/Down)

Сток знает только `TongueOut`, поэтому направления размечаются записью с подсказками:

1. `dotnet run --project MouthLink.Receiver -- --host <IP> --fps 0 --record d:\mouthrecon\t01.mlrec --prompts tongue`
   Голос (русский, если в Windows есть русский голос SAPI; иначе английский; `--voice off`)
   говорит «язык влево / вправо / вверх / вниз / прямо», между ними «убрать». Влево-вправо —
   в свою сторону. По умолчанию 3 круга по 4 с (`--rounds --hold --rest`), ≈2 мин; после
   последней подсказки запись останавливается сама. Рядом: `t01.stock.csv`, `t01.prompts.csv`.
   Между записями снимай шлем — каждая запись = отдельная посадка.
2. `python tools/mlrec_pair.py data/real3 "d:\mouthrecon\[st]*.mlrec" --tongue --size 160 --every 2`
   Внутри подсказок (без первых 0.8 с и последних 0.2 с) — направление по подсказке;
   вне подсказок 0, если сток видит «язык не высунут», иначе NaN. Поэтому старые записи
   без подсказок тоже дают полезные нули. Кадры подсказок прореживанием не трогаются.
   В выводе: сколько кадров каждого направления и стоковый TongueOut по подсказкам
   (если на «влево» он около нуля — язык не успевали высунуть, увеличь `--settle`).
3. Обучение как обычно; каналов становится 37.

## Всё лицо (--prompts face)

Сток неплохо видит симметричные выражения, но путает стороны, щёки и редкие позы, а
части каналов у него нет вовсе. Сценарий `prompts/face.json` даёт для каждой позы цель:

1. `dotnet run --project MouthLink.Receiver -- --host <IP> --fps 0 --record d:\mouthrecon\f01.mlrec --prompts face`
   78 подсказок (челюсть, губы, уголки, нос, щёки, язык, язык при широко открытом и почти
   закрытом рте — `tongue_jaw`, открытый рот с языком внутри — `mouth_open`, TongueOut 0,
   эмоции, речь), по умолчанию 1 круг ≈ 9,5 мин. В `tongue_jaw`
   при «рот почти закрыт» TongueOut размечен 0.5 (кончик языка), направление — 1.
   Диагонали (`tongue_left_down`, `tongue_right_down` в группе `tongue`) — оба направления по 0.7.
   `tongue_left_max` / `tongue_right_max` — язык до упора в уголок; `tongue_sweep` — язык медленно
   водят влево-вправо: TongueOut 1, а направления помечены `"unknown"` (NaN, в лосс не идут) —
   в каталоге у позы можно перечислить такие каналы. Время на позу в каталоге: `hold` (держать), `settle` (первые
   секунды не размечаются — ищешь движение), `tail` (конец не размечается — уже
   расслабляешься). Односторонние позы — hold 6 с, settle 2 с. `--skip id,...`,
   `--groups ...`, `--time-scale`, `--rounds`, `--catalog` — см. `--help`.
   В консоли видно id подсказки и её длительность: `УЛЫБКА ТОЛЬКО ЛЕВОЙ СТОРОНОЙ  ==========   [smile_left, 6 с]`.
2. `python tools/mlrec_pair.py data/face "d:\mouthrecon\[stf]*.mlrec" --face --size 160 --every 2`
   Каналы: 33 стоковых + `TongueLeft/Right/Up/Down` + новые из `new_channels` каталога
   (всего 44). Правила по кадру:
   - база — несглаженный сток;
   - сток `TongueOut` < 0.05 → направления языка и `TongueRoll` = 0; сток `CheekPuff`
     < 0.05 (`--neg-cheek`) → `CheekPuffLeft/Right` = 0; иначе новые каналы = NaN;
   - внутри подсказки после settle и до tail: при `zero_new` (по умолчанию) направления и
     новые каналы = 0, затем метки подсказки поверх (`labels`), включая стоковые каналы;
   - эмоции и речь (`zero_new: false`, пустые `labels`) — чистый сток.
   Отчёт «сток против подсказки» показывает позы, где сток далёк от цели (≥ 0.25) —
   там своя модель и должна обогнать сток. «Почти не двигались: …» — канал без
   положительных примеров (например, `TongueRoll`, если его пропускали).
3. `train.py` без изменений: NaN маскируются в лоссе, для редких каналов (язык и новые)
   печатается «узнаёт X %, ложных Y %». Нужно несколько сессий с разной посадкой — CV по
   сессиям.

Свой каталог: скопируй `prompts/face.json`, правь `ru`/`en`, `hold`/`settle`, `labels`;
id совпадающие с подсказками языка (`tongue_left` и т.п.) делают старые записи
`--prompts tongue` совместимыми.

## Файлы

- `make_synth_dataset.py` — синтетика с известной истиной: сессии с разной
  «посадкой» (сдвиг/масштаб/поворот/яркость) и неподвижный ориентир в кадре.
- `model.py` — `tiny` (CNN с нуля) и `mnv3` (MobileNetV3-small, опционально с
  весами ImageNet).
- `train.py` — обучение (см. ниже).
- `export_onnx.py` — экспорт в ONNX + сверка torch vs onnxruntime.
- `infer_demo.py` — прогон ONNX через onnxruntime на датасете или записи `.mlrec`.

## Обучение

```
python train.py --data DATA --out RUN [опции]
```

| Опция | По умолчанию | Смысл |
|-------|--------------|-------|
| `--arch tiny\|mnv3` | tiny | архитектура |
| `--pretrained` | выкл | веса ImageNet для mnv3 (torchvision скачает сам); BN энкодера заморожен, lr энкодера ×0.03 |
| `--split sessions\|frames` | sessions | деление train/val. `frames` оставлен только для сравнения — он завышает оценку |
| `--val-frac` | 0.2 | доля **сессий** в валидации; `0` — учить на всём (финальная модель) |
| `--val-groups f09,t02` | — | явный список валидационных сессий (имена записей; старый вариант — номера) |
| `--cv` | выкл | исключать каждую сессию по очереди; сводка в `cv-report.json` |
| `--aug none\|light\|strong` | strong | strong: масштаб 0.75–1.35, поворот ±10°, сдвиг, гамма, яркость, шум, отражение |
| `--epochs`, `--batch`, `--lr` | 10, 64, 2e-3 | на малых данных считай **шаги**, а не эпохи: при < 200 шагах будет предупреждение |
| `--data A,B` | — | несколько датасетов сразу (каналы и `--size` должны совпадать) |
| `--data A@0.3,B` | — | от датасета A взять случайные 30 % кадров (все сессии остаются) — для дообучения |
| `--frames-on auto\|gpu\|cpu` | auto | где держать кадры; auto — в видеокарте, если влезают с запасом `--vram-reserve` (2 ГБ) |
| `--oversample TongueRight:3` | — | кадры с меткой канала ≥ 0.5 попадают в эпоху в N раз чаще (слабая сторона, редкая поза) |
| `--init best.pt` | — | дообучение с готовой модели; arch из чекпойнта; по умолчанию 3 эпохи, lr 5e-4; с `--cv` нельзя |

Выход: `best.pt` (чекпойнт с архитектурой и правилами flip), `report.json`
(по эпохам, по каналам, по каждой валидационной сессии).

Рекомендуемый порядок на реальных данных:
1. `--cv` — честная оценка «как модель работает на новой посадке», видно худшую сессию.
2. `--val-frac 0` — финальная модель на всех сессиях.
3. `export_onnx.py` → ONNX для модуля VRCFT.

## Дообучение на новых записях

Старые записи заново спаривать не нужно, и обучать с нуля тоже:

1. Спарить **только новые** записи в отдельный датасет (с теми же `--face --size 160`):
   `python tools/mlrec_pair.py d:\mouthrecon\data\face2 d:\mouthrecon\f09.mlrec d:\mouthrecon\f10.mlrec --face --size 160 --every 2`
2. Посмотреть, как текущая модель справляется с новой посадкой:
   `python tools/mlrec_eval.py --onnx training\runs\face-final\mouth.onnx d:\mouthrecon\f09.mlrec`
3. Дообучить готовую модель на старом + новом (старое нужно, чтобы модель не забыла прежние
   посадки; 3 эпохи на ~400 тыс. кадров — минуты):
   `python train.py --data d:\mouthrecon\data\face,d:\mouthrecon\data\face2 --init runs\face-final\best.pt --out runs\face-ft1 --val-frac 0`
   Честная проверка на новой посадке: вместо `--val-frac 0` — `--val-groups f10` (f10 в обучение
   не попадёт), затем финальный прогон без неё.
4. `export_onnx.py --ckpt runs\face-ft1\best.pt --out runs\face-ft1\mouth.onnx`.

Полное обучение с нуля и `--cv` — изредка, когда накопилось много новых сессий или поменялся
каталог/каналы. Если кадры всех датасетов не помещаются в видеокарту, `train.py` сам оставит
их в ОЗУ и будет подавать батчами.

## Проверено на синтетике (CPU, 3000 кадров, 10 сессий с разной посадкой)

| Прогон | val MAE | Худшая сессия | Комментарий |
|--------|---------|---------------|-------------|
| tiny, light-aug, деление **по кадрам** | 0.033 | — | выглядит хорошо, но это самообман |
| tiny, light-aug, деление **по сессиям** | 0.048 | 0.054 | честная оценка на новой посадке; хуже всего widen |
| tiny, **strong**-aug, по сессиям, 10 эпох | 0.038 | 0.040 | аугментации масштаба/поворота закрывают разрыв |
| tiny, strong-aug, по сессиям, 20 эпох | **0.031** | 0.032 | лучше даже «оптимистичного» деления по кадрам |
| mnv3 (без ImageNet), strong, 10 эпох | 0.032 | 0.034 | ONNX совпадает с torch до 1.2e-7 |
| tiny, strong, 20 эпох, **без ориентира** | 0.039 | 0.043 | ошибка shiftX удваивается (0.031 → 0.060) |

Выводы, которые переносятся на реальные данные:
- Оценка по кадрам врёт; оценивать только по целым сессиям.
- Аугментации посадки (масштаб, поворот, сдвиг) — не украшение, а основа.
- Стабильный ориентир в кадре (у реальной камеры — например, блик) помогает
  отличить сдвиг шлема от движения рта; держи его в кадре, не обрезай кропом ROI.

## Найдено и исправлено при проверке

- **MobileNetV3 с нуля схлопывался в константу.** В torchvision momentum BN у
  MobileNetV3 = 0.01; за сотни шагов скользящая статистика не сходится, и в режиме
  оценки выход не зависел от кадра (train MSE 0.006, а val = предсказание среднего).
  При обучении с нуля momentum теперь 0.1; с `--pretrained` BN заморожен.
- **Кадров меньше, чем батч** — раньше не было бы ни одного шага обучения; теперь
  батч ужимается до размера выборки.

## Приватность

Кадры рта — снимки лица. Датасеты, записи и веса, обученные на твоём лице, —
только локально, в репозиторий не попадают (`.gitignore` закрывает `data/`,
`runs/`, `*.npy`, `*.onnx`, `*.pt`). Синтетический датасет лицом не является.
